1. Prerequisites

Before you start, make sure you have:

  • Web App running locally (make dev)
  • Integrations API running locally (cd api && npm run start)
  • Redis server running (integrations uses Redis)
  • Access to the Portamedic test study in WebApp
  • Portamedic sandbox credentials (client_id, client_secret, account #)

⚠️ Kodama Disabled Portamedic

Portamedic integrations were disabled due to erroneous logs. You may need to re-enable feature flags before testing. Check with Kodama for the specific ticket.

2. Check for Existing Credentials

First, check if we already have sandbox credentials configured:

Check Environment Variables

# In the integrations API directory
grep -ri "PORTAMEDIC" .env
grep -ri "integratedtestingservices" .env

Check Config Files

# Look for Portamedic config
cat api/src/common/configs/portamedic.config.json

Check Postman

Open Postman → Workspace: Curebase - Integrations API → Look for Portamedic collection with environment variables.

Expected Credentials

Type Variable Name Description
REST API PORTAMEDIC_CLIENT_ID OAuth2 client ID for token service
REST API PORTAMEDIC_CLIENT_SECRET OAuth2 client secret
SOAP API PORTAMEDIC_USERNAME SOAP API username (strUserName)
SOAP API PORTAMEDIC_PASSWORD SOAP API password (strUserPassword)
Both PORTAMEDIC_ACCOUNT_NUMBER 5-digit account number

4. Configure Portamedic in WebApp

Step 4.1: Find or Import Portamedic Test Study

There should be a test study specifically for Portamedic. Look for "Portamedic Test" or similar.

Step 4.2: Configure Netera Blood Draw Settings

Navigate to the study settings:

Study → Settings → Netera Blood Draw → Settings

⚠️ Important

The key in "Netera Blood Draw" settings is environment-specific. You need different keys for sandbox vs production.

Step 4.3: Configure Portamedic Fields

In the Portamedic configuration section, fill in:

Field Required Description
Account Number ✅ Yes 5-digit account from Portamedic
Service Set Name ✅ Yes e.g., "Blood Draw"
Service Set RefID ✅ Yes Agreed ID with Portamedic
Contact Name No Contact for field office issues
Contact Phone No Contact phone number
Contact Email No Contact email

Step 4.4: Enable the Integration

Make sure the Portamedic toggle is enabled. Save the configuration.

📸 Screenshot: Portamedic configuration panel in WebApp settings

Step 4.5: Configure Site & Availability

You need to set up a Portamedic clinic with availability:

Sites → Add Clinic → Portamedic Clinic

Configure availability slots for the Portamedic clinic. This is required for the scheduling flow to work.

5. Test the Integration

1

Create a Test Participant

Create a new participant in the Portamedic test study.

2

Use a Valid Zip Code

Use zip code 11738 - this is known to have Portamedic availability. Many zip codes have no coverage!

3

Fill Required Fields

Complete the prescreening form with:

  • Date of Birth (DOB)
  • Address (with valid zip code)
  • Medical Procedure Date
4

Sign Documents

Complete any required document signatures.

5

Schedule a Visit

Go to scheduling and look for Portamedic availability. Select a time slot and book.

ℹ️ What Happens Behind the Scenes

  1. WebApp calls GET /api/scheduling/availability
  2. Integrations API calls Portamedic SOAP CheckAvailabilityWithRequirements
  3. Available slots returned with examinerID
  4. On booking, ON_SCHEDULE event fires
  5. Integrations API calls MakeReservation then NewCaseSubmit

6. Verify It's Working

Check the Integrations Tab

In the participant view, go to the Integrations tab. You should see:

✅ Success Indicators

  • services.portamedic: true
  • successful: true
  • Reservation object with Portamedic IDs
  • Order object with case number

Check Raw Data

Click "Raw Data" to see the full integration response:

{
  "services": {
    "portamedic": true,
    "datavant": false,
    "vdoc": false
  },
  "integrations": {
    "portamedic": {
      "reservation": { ... },
      "order": {
        "caseNumber": "CLIN1A347226",
        ...
      }
    }
  }
}

Check Integrations API Logs

In your terminal running the Integrations API, you should see:

# Events received
ON_SCHEDULE event received
Portamedic service starting...
CheckAvailabilityWithRequirements called
MakeReservation called
NewCaseSubmit called
Portamedic order successful

7. Troubleshooting

No Availability Showing

Cause Solution
Invalid zip code Use 11738 - known to have coverage
No site availability configured Set up Portamedic clinic with availability slots
Reservation date too soon Must be 5+ days in the future
Invalid credentials Check SOAP username/password

Integration Not Triggering

Cause Solution
Webhook URL not set Check study settings → webhook URL
Integrations API not running Start with npm run start
Feature disabled by Kodama Check feature flags, re-enable
Portamedic toggle off Enable in study settings

Authentication Errors

# Test token endpoint directly
curl -X POST "https://auth.integratedtestingservices.com:8020/TokenService/connect/token" \
  -H "Content-Type: application/x-www-form-urlencoded" \
  -d "grant_type=client_credentials&client_id=YOUR_ID&client_secret=YOUR_SECRET"

# Expected success response:
{
  "access_token": "eyJhbG...",
  "expires_in": 300,
  "token_type": "Bearer",
  "scope": "Clinical.Originator"
}

# Error response (invalid credentials):
{"error":"invalid_client"}

Common Error Messages

Error Meaning
invalid_client Wrong client_id or client_secret
strAccountNumber must be 5 chars Account number format wrong
No examiners can cover this scenario No coverage for that zip code
datReservation must be 5 days out Book further in advance
strUniqueID already exists Duplicate order - use new participant
